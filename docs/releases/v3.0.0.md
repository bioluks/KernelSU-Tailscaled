# KernelSU-Tailscaled v3.0.0 — Android companion

This release adds an optional Android companion for Taildrop sharing, module
controls and completed-file notifications. It uses the module's existing
Tailscale connection; no separate VPN or login is needed.

English remains the default, Simplified Chinese remains available, and Headscale
sign-in and automatic Taildrop delivery are unchanged. The bundled Tailscale
engine remains **1.104.2**.

## Install

- **Universal module:** `KernelSU-Tailscaled-v3.0.0.zip` (ARM and ARM64).
- **ARM64 module:** `KernelSU-Tailscaled-arm64-v3.0.0.zip`.
- **32-bit ARM module:** `KernelSU-Tailscaled-arm-v3.0.0.zip`.
- **Optional app:** `KernelSU-Tailscaled-companion-v3.0.0.apk` (Android 8.0+).

Install the module over the existing `kernelsu-tailscaled` installation in
KernelSU Manager. Do not uninstall or delete `/data/adb/kernelsu-tailscaled`
first. Existing login, preferences and Taildrop destination are retained; no
Android reboot or fresh sign-in is requested. Version code **30000000** advances
all earlier published and private combined-module builds.

The APK is separately installed and requires root approval in KernelSU. It is
never silently installed by the module. Keep the published release signer when
upgrading; branch CI debug APKs have a different signer.

## Companion behavior

- Select files in another app, then **Share → Tailscaled Companion → device →
  Send**, or use **Choose files to send** inside the companion.
- The device picker uses the official Taildrop-eligible device list. Headscale
  must advertise file sharing. Android controls Direct Share suggestion placement;
  the in-app picker remains available.
- Files stream from granted content URIs into the module's effective CLI and
  socket, without whole-file cache copies, a second daemon or an Android VPN.
- A foreground notification runs only during sending and provides **Cancel**.
  Progress measures bytes supplied to the CLI; success waits for CLI completion.
  Android 15+ background data-sync time limits cancel an overlong transfer.
- Native controls expose status, enable/disable, restart, logs and an external
  link to the full loopback panel. Advanced configuration stays in the WebUI.
- **Allow receive notifications** enables optional notifications after successful
  module-owned saves. Closing, force-stopping or uninstalling the app does not stop
  automatic delivery. No idle app polling or app boot service is added.

The companion defaults to English and remembers its English/Chinese selection.
Text-only and URL shares are not converted into files. Receive notifications
report completed saves, not incoming-transfer progress.

## Verification

The on-device results below are from the preceding companion build, whose
runtime and app source are unchanged in 3.0.0. This version changes release
metadata and documentation; it does not claim a new on-device verification run.

On the connected rooted ARM64 phone, in-app file selection and the actual
Material Files Android share sheet both sent a file to the Mac with matching
SHA-256. Mac-to-phone delivery also matched SHA-256, including a filename with
spaces, Unicode, an apostrophe and ` as `. Completed-receive notifications were
observed, and another file arrived with the app force-stopped and no app service
running. Native controls and the language switch were exercised on the phone.

A 256 MiB send matched SHA-256. A temporary on-device instrumentation harness
verified cancellation during blocked provider query/open, rejection of a stale
process-start identity, cancellation of the owned header reader, two identical
successive completion updates, and picker-result resumption during a status
request. Exact original Tailscale preferences were retained after the final
module upgrade. No companion service remained after transfers completed.

Focused Linux runtime regressions cover binary stdin preservation, eligible
peer checks, malformed headers, effective engine selection, cancellation PID
ownership, lock-free sending, safely quoted receipt names and notification
recovery after a partially failed receive batch. All three module package
architectures are validated. GitHub Actions repeats the release gates and
requires release signing, exact assets, immutable publication and asset verification.

Equivalent on-device coverage for 32-bit ARM, every document provider, long-term
battery behavior and Android's six-hour foreground-service limit is not established.
This is not an official Tailscale or KernelSU release.
